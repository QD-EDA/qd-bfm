# M10b: AXI handshake overlay

M9 scope is the 162 stock-firmware top-level rows; its 109 authored-stimulus/generated-UVMF rows remain `NOT_RUN_NON_FIRMWARE`. The 103-row M10b overlay selection contains only M9 firmware PASS rows and includes all six exact M8 rows. No UVM bench is being ported.

The current candidate changes only the pinned `axi_if.sv` BFM's AR, AW, W, and B handshake timing under Verilator: channels use nonblocking drives, wait on `posedge clk`, and sample peer ready/valid through clocking-block inputs (`#1step`). RTL, firmware, assertions, and pass criteria remain unchanged. Pinned `axi_if.sv` SHA-256: `e03bd7a7654eb9c31bd532861b94d59c876810aa9798f9f67f7df2a5a3f5495c`; current AR/AW/W/B candidate overlay SHA-256: `d387d149e6956d5e19b7fc6c1f86c31b115f60b743439a37f1040fd2300968b1`. The immediately previous AW/W/B-only overlay was `e8fec740da3fb9ffcd72fd7eb72c63480d30bd4de531e390772138dcf9ad6d1a`; earlier AW-only (`c829840c8e147fdf249be51c404227977d6112a96d3baa2d51d455775e330fa0`) and AW/W (`782c46c617c90111bd3ca91cab2739ca6d548ebfeb1a56d83b4b482ac6ff033f`) candidates advanced successively from AW to W to B assertions. ## `smoke_test_mbox` trace

The existing M9 trace shows 20 successful AXI reads returning `RDATA=1`, but did not settle whether Verilator scheduling or the CSR RTL caused the first-read difference. Diagnostic jobs 1779–1781 stopped before the target read. Job 1782 reached it: at CSR cycle 56915 the decoded read sees lock value 0, `next=1`, `load=1`, and readback 0; after the edge the lock is 1, while the first AXI response is logged as `RDATA=1`. Job 1784 resolves the cause: at AXI posedge cycle 56942, `rvalid=1`, `rready=1`, and the active sample sees `rdata=0`; after updates in that same time slot, `rdata=1`, which the live `@(posedge clk)` task returns. The preceding negedge had data 0. This is a testbench sampling race at the read-to-set handoff; the Icarus one-poll grant is consistent with the old value. The diagnostic runs hit their outer 180-second caps and are not official test results. Their logs and verified manifests are under [`diagnostics/mbox-lock-trace/`](diagnostics/mbox-lock-trace/).

The MBOX root cause, 103-row pinned-versus-overlay comparison, per-row speedups, and SHA512 assertion discrepancy are recorded. The SHA512 finding is diagnostic only; the operational overlay leaves RTL, assertions, firmware, and pass criteria unchanged.
