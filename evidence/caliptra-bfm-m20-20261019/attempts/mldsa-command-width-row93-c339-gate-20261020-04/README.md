# Row 93 command-width overlay gate — combined fix

This fresh one-row gate covers both native helper command writers: the M16 predictor calls and the randomized sequence `*_for_test.hex` sign/verify commands. The per-run overlay sizes sign/verify commands in `ML_DSA_randomized_verif_sequence.svh` and `ML_DSA_randomized_two_verif_on_fail_sequence.svh`, plus the predictor `op_code-1` expressions. It does not change RTL, firmware, input vectors, pass criteria, or assertions.

Source pins: Caliptra `49370266d12cb0c4a8f71b3a0ff7e54ba7d4866e`, Adams Bridge `b77e3d899e828d626cfc2a0d26a6b5704cc121e0`, Icarus c339 `cae035642e056644274a01e98d4422ce286685b4`. Icarus and `vvp` local build hashes are recorded in `../../toolchain-c339-local-20261020/raw/`. One local simulation, one thread, 1,800-second runner timeout and 2,100-second `localrun` cap.

Result: local c339 Icarus compiled successfully but reached the 1,800-second VVP cap (1799.297 seconds; peak RSS 751,828,992 bytes), with no testcase marker or UVM error/fatal. At 55,085 ns the corrected sequence had loaded nonzero signature words and the predictor had run the verification helper; `verif_input.hex` starts with command `02`, and `verif.log` records command `02` and result `0`. Pinned helper source confirms `if (!ret)` writes the success payload, so result `0` means its reference verification passed. The next sequence code is its `while (!valid)` status polling, but no later result-read log appears before timeout, so the log does not distinguish a stuck first status read from an unasserted status bit. The `[PRED_RUN_EXE] The IP is locked` banner is emitted by predictor code whenever `lock_IP` is set after starting an operation, so it is not evidence of the hang cause. Result JSON is `output/result.json`; the combined evidence archive is `raw/row93-combined-overlay-c339-timeout.tar.gz`, SHA-256 `13fad4870ad9d5b57bd67145f3c704b41dffb62faeef1487f6d314f1c121667b`.

This local timeout is diagnostic, not the final pinned-host verdict. A fresh Slurm gate with a 3,600-second runner cap is staged separately; no model change is made by extending the runtime cap.
