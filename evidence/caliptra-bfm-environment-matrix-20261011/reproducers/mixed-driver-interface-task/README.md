# AXI interface task and continuous-driver root cause

The 46 errors in the Caliptra top are a testbench portability problem, not an Icarus defect. In the pinned Caliptra source (`49370266d12cb0c4a8f71b3a0ff7e54ba7d4866e`), `src/axi/rtl/axi_if.sv:180-207` defines `rst_mgr()` with procedural assignments to 23 manager-side interface variables. `src/integration/tb/caliptra_top_tb_axi_complex.sv:427-464` and `:596-632` continuously assign those same fields on `axi_sram_if` and `axi_fifo_if`. The 23 field names match the c339 errors on each interface. The local `axi_sram_if`/`axi_fifo_if` reset tasks are not called in the compile snapshot; c339 nevertheless sees their possible procedural writers in the interface definition.

IEEE 1800-2023 §6.5 (pp. 90-91) says a variable cannot have continuous and procedural assignments writing the same bit. The `rst_mgr()` task's assignments are procedural, so these testbench variables violate that rule. §6.5 also says a `force` is neither a continuous nor procedural assignment; §10.6.2 (p. 257) describes force/release and independently disallows applying it to a variable with mixed continuous/procedural assignments. The randomized delay macro is not the source of the conflicting writer; the interface reset task is.

The minimal reducer preserves that interface task, continuous assignments, subordinate modport, and force/release. With Icarus c339, the baseline rejects both variables; compiling the same source with `-DSYNTHESIS` removes the guarded reset task and then compiles and simulates successfully. Verilator 5.051 accepts and runs the baseline reducer. That acceptance is simulator tolerance, not evidence that the mixed assignments conform to the standard. Therefore no Icarus issue is filed for the mixed-driver diagnostics. The separate `caliptra_top_tb.sv:138` clock-generator diagnostic is tracked by #545 and is now reproduced from the actual source: c339 rejects the extracted clock code and Verilator 5.032 passes it. The old bit-versus-logic distinction remains unconfirmed; this does not affect the separate mixed-driver portability finding.

The reducer source, c339 baseline/control logs, Verilator run, host and tool provenance are retained beside this report. The full Caliptra testbench was not compiled with Verilator; Verilator acceptance here is for the reduced driver pattern.
