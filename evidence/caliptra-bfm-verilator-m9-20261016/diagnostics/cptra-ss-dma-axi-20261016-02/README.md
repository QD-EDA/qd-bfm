# DMA AXI response trace

Diagnostic job 1763 on DAN-DESKTOP rebuilt the pinned Caliptra top model with Verilator 5.052 and ran only `cptra_ss_test_rom`, seed 1. The pinned Caliptra RTL revision is `49370266d12cb0c4a8f71b3a0ff7e54ba7d4866e`; the built model SHA-256 is `e218a02c317548903057b90b2baec587f54170be5e600f1fc9bb0389faf9c495`. The overlay adds logging only to the DMA controller and SoC-IFC arbiter.

The diagnostic reached the 16th DMA FIFO write at simulation time 5,973,000. Word `0x67120ad3` was accepted with `dv=1`, `hold=0`, `wr_stall=0`, `fifo_valid=1`, `fifo_ready=1`, depth 15, and `full=0`; all 16 words then drained. The AXI write returned `BRESP=11` (DECERR). The controller set `AXIERR=1` while `MBOXERR`, `AESERR`, and `KVERR` stayed zero, then entered state 3 (`DMA_ERROR`). This rules out a FIFO-full stall at word 15: the accepted write is followed by an AXI decode error.

The firmware uses DMA destination `0x21200000` in `cptra_ss_test_rom.c:89`. The pinned top testbench config declares a 256 KiB SRAM at `0x0001_2344_0000` and a FIFO window at `0x0000_fa57_0000` (`caliptra_top_tb_pkg.sv:107–116`); neither contains `0x21200000`. This map mismatch is consistent with the observed DECERR and is the likely initiating cause of the DMA error. See the pinned [firmware destination](https://github.com/chipsalliance/caliptra-rtl/blob/49370266d12cb0c4a8f71b3a0ff7e54ba7d4866e/src/integration/test_suites/cptra_ss_test_rom/cptra_ss_test_rom.c#L85-L95), [testbench AXI windows](https://github.com/chipsalliance/caliptra-rtl/blob/49370266d12cb0c4a8f71b3a0ff7e54ba7d4866e/src/integration/tb/caliptra_top_tb_pkg.sv#L103-L116), and [DMA error-state logic](https://github.com/chipsalliance/caliptra-rtl/blob/49370266d12cb0c4a8f71b3a0ff7e54ba7d4866e/src/axi/rtl/axi_dma_ctrl.sv#L366-L397).

The trace includes a CPU read of `STATUS0` at offset `0x2200c` (the pinned generated header address is `0x3002200c`), but the overlay logs request fields only, not the returned register data. Other accesses to `0x22818` are not the `STATUS0` read. Diagnostic 03 (job 1766) initially filtered on that wrong address and was canceled before a result; see its [cancellation record](../cptra-ss-dma-axi-20261016-03/README.md). Diagnostic 04 (job 1769) uses the verified `0x2200c` offset to capture `uc_rdata`. The official M9 row remains TIMEOUT; this 600-second diagnostic is separate evidence, not a replacement result. The c339 row also has no terminal test result, so this is not a finished-result disagreement.

The simulator exited on the 600-second diagnostic cap (`sim_exit=124`, 600.004 seconds; total runner wall 602.578 seconds). The build peaked at 2,359,752 KiB RSS; the simulation peaked at 55,424 KiB. The checksum-verified archive is [`diagnostic-evidence.tar.gz`](diagnostic-evidence.tar.gz), SHA-256 `41379682e1f9bb4abd2efe32035dadd9a5834fcd8bd9c3d9403d890a4c6ed4ab`; it includes the extracted logs, the verified source snapshot, and its source-file manifest.

After the archive and source manifest passed local verification, the completed remote run tree and its transfer archive were deleted, freeing 711,546,287 bytes (about 0.66 GiB). Shared toolchains were untouched.
